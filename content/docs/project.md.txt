# Ataxx 專題研究規格

> 全域版本與語義規格請以 [`SPEC.md`](SPEC.md) 為準；本文件只描述研究問題與方法方向。

## 題目

**基於局面與分支波動性之 Ataxx 自適應選擇性搜尋**  
*Volatility-Aware Adaptive Selective Search in Ataxx*

## 核心問題

1. **Search Instability**：不同搜尋深度下，最佳走法與 move ranking 多常改變？
2. **Volatility Detection**：能否用便宜的盤面或淺層搜尋資訊預測這種改變？
3. **Position-Level Selective Deepening**：依局面 volatility 分配搜尋深度，能否取得比固定深度更好的 strength/cost tradeoff？
4. **Branch-Level Selective Deepening**：能否只對高 volatility 的候選分支額外深化？

主線：

`Search Instability → Volatility Detection → Position-Level → Branch-Level Selective Deepening`

## 目前實作方法

- Baseline / reference search：**Fixed-depth Alpha-Beta**。
- V3/V4 正式研究使用彼此獨立的 d2 / d4 / d6 search calls。
- `d6` 是較深 reference search，不等於 ground truth 或 perfect play。
- Volatility 候選訊號包含 best-move disagreement、score swing、淺搜 node growth、感染數、mobility、legal move count、piece difference 等。
- Oracle analysis：可在正式 outcome 凍結後，離線補算較深搜尋，以估計 missed instability / selective-deepening 上限。

**Iterative Deepening 尚未作為目前 V3/V4 的正式 baseline 實作或使用。**若未來加入，必須另做 implementation / verification / protocol version，不能把它描述成已完成方法。

比較不同方法時，應同時報告 **nodes** 與 **wall-clock**。Nodes 為較不受硬體影響的主要計算成本 proxy；wall-clock 用於實際執行效率參考。

## 評估

- Best-move agreement with deeper reference
- Move instability / score swing
- Volatility detector discrimination / calibration
- Paired color-swapped game score rate
- Nodes searched
- Time per move / game
- Realized deepen fraction
- Stable / volatile position 的分組錯誤率

## 範圍

主實驗使用標準 `7×7`、無障礙 Ataxx，V3 detector 的正式適用範圍為 ply 6–30。

現有 `N×N` 引擎與 Procedural Level Generator 保留作延伸，可研究棋盤尺寸、障礙與 topology 對 volatility 的影響。Othello 可作跨遊戲驗證，但不是目前主線。

## 研究進程

1. 核心引擎與測試
2. Fixed-depth Alpha-Beta
3. Position sampling + search logging + deeper reference
4. Search Instability 統計
5. Volatility Detector
6. Position-Level Selective Deepening
7. Offline missed-instability / oracle diagnosis
8. Branch-Level Selective Deepening
9. 固定／可比較計算成本的完整 strength-cost 分析

CNN/GNN、PLR、GA 與大型強化學習目前不列入主線。
