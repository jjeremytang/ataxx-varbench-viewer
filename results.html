2026-08-20～22 · Engine & Search Validation

Ataxx Engine、Alpha-Beta 與 Search Logging

研究起點
為什麼先做這個？

如果 legal move、infection、pass、terminal、search score 或 node count 有錯，後面所有 instability 與 detector 結論都沒有意義。

做了什麼

  • 完成 Ataxx 核心規則與一般 N×N 棋盤。
  • 建立 fixed-depth Alpha-Beta、stable move ordering、search logging。
  • 建立可重現 positions / seed 流程與測試。

結果

程式與測試通過，能輸出 best move、score、depth、nodes；之後所有正式研究都以同一 authoritative C++ engine 為基礎。

研究意義

這不是用來證明科學假說的實驗，而是建立後續研究的 measurement instrument。它的成果是「我們有一個可重現、可驗證的搜尋器」。

不能宣稱

Alpha-Beta 驗證通過本身不代表 search instability 存在，也不代表 selective deepening 有效。

因此下一步

固定一批局面，在不同 depth 上搜尋，直接量測 best move 是否改變。

Phase B · 第一個核心現象：Search Instability

E1 · Search Instability — d2 / d4 / d6

第一次正式量出：搜尋加深真的常改變 Ataxx 的最佳走法

2026-08-22
Research question

標準 7×7 Ataxx 中，best move 是否會隨搜尋深度增加而頻繁改變？而更深搜尋的成本又有多大？

設計

  • 標準 7×7、無障礙。
  • 1,000 個固定 positions，sampling ply 6–30。
  • 每局面搜尋 d2、d4、d6，共 3,000 search records。

主要指標

  • best-move flip rate
  • evaluation-score swing
  • node growth
  • 依 early / mid / late 描述 instability
38.0%d2 → d4 best-move flip
32.6%d4 → d6 best-move flip
45.4%d2 → d6 best-move flip
51.8%至少一次改變 best move
178.5d2 median nodes
6,888d4 median nodes
226,438d6 median nodes
≈1269×d6 / d2 median node cost
研究意義

這是主線成立的第一個關鍵證據：Ataxx 中更深搜尋不只是「算得更多」，而是經常真的改變 decision；但 d6 成本又遠高於 d2/d4。這同時建立了「值得加深」與「不能全部加深」兩個條件。

限制

21 個特別困難 positions 為完成 d6 使用較大的 transposition table，因此跨 position 的 node-cost 比較仍屬 preliminary；此外 d6 也不是 ground truth。

因此下一步

不再問「有沒有 instability」，而改問「能不能用便宜訊號提前知道哪些局面會 instability」。

Research question

淺層搜尋的 move disagreement、node growth、branching 等 cheap features，是否和更深層 move change 有描述性關聯？

資料

  • 10×10，20% 障礙。
  • 16 worlds、32 games、3,802 positions。
  • special worlds vs control。
  • 研究型態：exploratory_case_control。

為什麼不是正式 population study？

special worlds 是依之前 outcome patterns 挑選，因此 sampling 有意偏向特定案例；這個階段只拿來找「哪些 features 值得帶進下一版」。

46.90%all d2→d3 move change
45.11%all d3→d4 move change
46.16%all d2→d4 move change
0.6022node_growth_2_4 rank AUC

單一 feature 訊號

  • node_growth_2_4: AUC 0.6022
  • branching_factor: AUC 0.5730
  • score_swing_2_4: AUC 0.5465

觀察

單一 feature 都只有弱到中弱的 discrimination，顯示「一條人工 threshold」很可能不足，需要多變量模型。

研究意義

V2 沒有證明某種 topology 一定更 volatile；它真正完成的任務是：確認 cheap features 裡有一些 signal，但單一 feature 不夠強，因此值得進一步建立無偏 7×7 dataset 並做 multivariate detector。

不能宣稱

不能用這組 46% 左右的 flip rate 當成一般 Ataxx population prevalence；也不能從 special/control 差異推論障礙 topology 的因果效果。

因此下一步

回到主研究設定：標準 7×7、無障礙、固定 sampling protocol，建立可以真正 train / validation / test 的正式 dataset。

V3-01 · Formal Volatility Dataset Protocol

先凍結資料規格，再跑正式資料

2026-08-24
目的

把 V2 的探索與 V3 的正式驗證隔離，避免看過結果後再改 sampling、feature leakage 或 split 規則。

主要規則

研究意義

V3-03A · Feature / Model Selection

單一 feature 不夠：Logistic Regression 成為 locked detector

2026-08-24
Research question

哪些 cheap features 有 predictive signal？多變量模型能否比單一 feature 更有效辨認未來 d4→d6 flip？

Validation 上最強單一 feature

  • move_changed_2_4: ROC-AUC 0.6529
  • d4_score: 0.6202
  • d4_nodes: 0.5925
  • node_growth_2_4: 0.5922

候選模型

比較多個 Logistic Regression regularization 與 shallow Decision Tree；majority baseline ROC-AUC = 0.5。

0.7218selected validation ROC-AUC
0.5308selected validation PR-AUC
C = 0.01locked logistic configuration
M1locked model family

20% validation deepen budget

flip recall 34.11%、precision 60.83%、recall lift 1.71×；policy node proxy 約 fixed d6 的 31.65%。

為什麼選 Logistic

Validation performance 優於 tree candidates，且模型簡單、可解釋、容易嵌入 C++ online policy。

研究意義

局面／淺搜資訊中存在可組合的 predictive signal；多變量模型比任何單一 heuristic 更好。這一步才真正把「volatility」從概念變成可計算 detector score。

重要方法邊界

這些結果仍是 validation；在看到 test 前，model family、C、preprocessing 與 feature set 必須鎖定。

因此下一步

使用已鎖定 selection.json 對完全未參與 model selection 的 600-row test split 做一次性評估。

Detector 的 predictive signal 在 unseen test 上保留下來

2026-08-24～25
Research question

預先鎖定的 detector 在沒有參與選模的 test positions 上，是否仍能辨認 d4→d6 instability？

0.7183test ROC-AUC
0.5301test PR-AUC

Test 上 20% ranking budget

63 / 207 flips captured；recall 30.43%、precision 52.50%、recall lift 1.52×；node proxy 約 fixed d6 的 29.68%。

Largest model terms

move_changed_2_4 為最大正向項；node growth 亦為正向訊號。這些係數描述的是模型內 association，不應被當成因果效果。

研究意義

Validation ROC-AUC 0.7218 與 test 0.7183 非常接近，顯示 predictive signal 並未在 unseen split 明顯崩潰。此時才有足夠理由把 detector 真正部署到搜尋器。

不能宣稱

這只證明 out-of-sample predictive signal；尚未證明 detector-guided policy 能提高實際 win rate，也不能證明每個 d6 change 都更好。

因此下一步

把 detector score 轉成預先固定的 selective-deepening threshold，然後做真實對弈。

E3-001 / V4-01 · Position-Level Selective Deepening

Detector-guided deepening 第一次轉化成實際棋力提升

2026-08-25
Primary research question

PSV-20 能否比 fixed d4 強，同時使用遠少於 fixed d6 的搜尋成本？

正式設計

  • 50 個預先凍結 openings。
  • PSV-20 vs P4：100 games。
  • PSV-20 vs P6：100 games。
  • 每 opening 交換顏色，總計 200 games。
  • threshold 在 outcome 前已凍結。

政策

P4 = fixed d4；P6 = fixed d6；PSV-20 = d4 + ply 6–30 detector gate + triggered d6。

59.0%PSV vs P4 score rate
56W / 6D / 38LPSV vs P4
51–67%paired bootstrap 95% CI
6.40×PSV / P4 nodes
21.0%PSV vs P6 score rate
18W / 6D / 76LPSV vs P6
13.5–29.0%paired bootstrap 95% CI
13.37%PSV / P6 nodes
7,738formal PSV moves
2,336detector-eligible moves
554triggered d6 calls
67.87%triggered calls changing d4 move
研究意義

這是目前最重要的 deployment 證據：predictive signal 不只停留在 AUC，而是真的能改善相較 fixed d4 的對弈表現；同時相較 fixed d6 只用約 13% nodes，證明 selective computation 有實際節省空間。

但結果也揭露明顯缺口

PSV-20 對 P6 只有 21.0% 得分率，遠不能說「已接近 d6 棋力」。而且相較 P4，59% 的棋力提升是用 6.40× node cost 換來的，因此目前 policy 仍不是最終理想 tradeoff。

因此下一步

先診斷到底漏掉多少未觸發 instability，再決定應調 budget、改善 detector recall，或進入 branch-level selective deepening。

模型、政策、對弈結果：三者不能混在一起

Volatility Detector

輸入 24 個局面與淺搜 features，輸出 d4→d6 best-move disagreement 的 model score。主要評估 ROC-AUC / PR-AUC / recall / precision。

PSV-20 Policy

使用固定 threshold 決定某個 eligible position 是否從 d4 加深到 d6。它是 resource-allocation policy，不是分類模型本身。

Game Strength

真正的棋力必須由 color-swapped games 評估。59% 是 PSV-20 對 P4 的 score rate，不是 detector accuracy。

目前整條研究鏈支持到哪裡？

✓Search Instability 在 Ataxx 中明顯存在
✓Cheap features 對 instability 有 out-of-sample predictive signal
✓Detector-guided d4→d6 deepening 可改善相較 fixed d4 棋力
✓相較 fixed d6 可節省大量 nodes
✗尚未證明目前 policy 已接近 d6 或是最佳 budget / granularity
最嚴格的總結：目前證據支持「volatility-aware computation allocation 是可行而且有實際效益的方向」，但尚未解決如何在固定資源下逼近更深搜尋的最佳 tradeoff。
