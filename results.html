核心：Detector 不直接預測最佳走法，也不預測勝率；它預測的是「d4 的決策是否會被 d6 推翻」，因此角色是 adaptive computation allocator。

Locked Volatility Detector：模型本身的正式定義

Target

預測 d4 → d6 best-move disagreement

y = 1 ⇔ best_move(d4) ≠ best_move(d6)；完整 move identity 不同才算 positive。y=0 表示 d4 與 d6 選擇相同 best move。

Model family

L2 Logistic Regression

Locked model ID：M1_logistic_C_0.01，inverse regularization strength C=0.01。模型用 train 1800 rows fitting；family 與 C 由 validation PR-AUC 事前選定。

Data boundary

只允許 d4 結束時已知資訊

任何 d6_*、target label、split、position ID 或由 test labels 洩漏的資訊都禁止進入 predictor。

Interpretation boundary

輸出不是「這步棋正確的機率」

它是對 P(d4 best move 在 d6 改變) 的 Logistic model probability estimate。d6 本身仍不是 objective ground truth。

2. Preprocessing

Log transform

四個非負且偏態的搜尋量先做 log1p(u)=ln(1+u)：d2_nodes、d4_nodes、score_swing_2_4、node_growth_2_4。

Train-only standardization

所有 numeric model columns 再用 train-set 固定參數標準化：z=(u−μ_train)/σ_train。Validation、test、以及後續 online deployment 都必須沿用同一組 μ、σ，不得重新估計。

3. Logistic score 與 probability

η(x) = β₀ + Σⱼ βⱼ φⱼ(x)

p̂(x) = σ(η) = 1 / (1 + exp(−η))

其中 φ(x) 是上述 one-hot + train-standardized 24 維向量。p̂ 越高，模型判定「d4 best move 會在 d6 被推翻」的風險越高。

5. 從模型到 PSV-20 policy

Detector

算出 p̂(x)

模型只輸出 volatility probability estimate；本身不決定最後走 d4 還是 d6。

PSV-20 gate

p̂(x) ≥ 0.500931073443522

在 policy 適用的 ply 6–30，若 score 達 fixed validation-derived threshold，就觸發 d6；否則保留 d4。Threshold 在正式 outcome 前已凍結。

模型、政策、棋力三層定義

Model

p̂=P(d4→d6 move change | d4-known features)。Locked L2 Logistic，24 維 encoded input。

Policy

PSV-20 用固定 threshold 把 model score 轉成「是否跑 d6」。

Game Strength

只能由 paired color-swapped games 衡量；59% 是 vs P4 score rate，不是 model accuracy。

目前證據邊界

✓Search Instability 明顯存在
✓Cheap features 有 out-of-sample signal
✓Detector-guided deepening 可改善 d4
✓相對 d6 節省大量 nodes
✗尚未證明接近 d6 或找到最佳 budget/granularity
嚴格總結：目前支持 volatility-aware computation allocation 的可行性與實際效益，但還沒有解決固定資源下如何逼近深搜的最佳 tradeoff。
